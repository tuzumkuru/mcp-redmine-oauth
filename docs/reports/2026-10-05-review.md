## 1. Claude Code login failure

**Symptom.** The authorize step returned:

```
{"error":"invalid_request","error_description":"Redirect URI 'http://localhost:39315/callback' does not match CIMD redirect_uris."}
```

**Cause.** Claude Code identifies itself with a Client ID Metadata Document (CIMD) at `https://claude.ai/oauth/claude-code-client-metadata`, which lists `http://localhost/callback` and `http://127.0.0.1/callback` with no port [1]. It then listens on a random local port. FastMCP before 3.2.0 compared the port too, so no callback ever matched. RFC 8252 § 7.3 requires a server to accept any port on a loopback redirect URI [2].

**Evidence.**
- Against the deployed server, the same authorize request returned 400 with port `39315` and 302 to Redmine's login without a port.
- `matches_allowed_pattern` returns False for `http://localhost:39315/callback` against both CIMD patterns on FastMCP 3.1.1, and True on 3.4.8. On 3.4.8 it still rejects `http://localhost:39315/evil` and `http://localhost@evil.com/callback`.
- The fix is PrefectHQ/fastmcp#3589, first released in 3.2.0 [3].

**Fix.** v0.5.1 requires `fastmcp>=3.4.8,<4` (DR-001). The deployed server ran FastMCP 3.0.2; after the update the authorize request with port `39315` redirects to Redmine, and Claude Code logs in and calls tools.

## 2. PR #2: persistent token store, scope-aware tool visibility, observability

One commit, +452/−98, opened 2026-03-09 by an AI agent. Merges cleanly onto `main`.

| Area | Finding |
|---|---|
| Token storage | Replaces FastMCP's default Fernet-encrypted store with a hand-written SQLite store; the upstream refresh token is readable in plain text |
| Redis | `RedisStore(token_store_url)` raises `TypeError`: the constructor takes `url=` as keyword |
| Default path | `sqlite:///.data/token_store.db` resolves to `/.data/token_store.db`; in the container the app directory is root-owned and the process runs as a normal user, so the first write fails |
| Tool visibility | `ctx.disable_components(...)` works on FastMCP 3.4.8, but `get_context()` raises outside a request, which breaks 7 existing tests; the session set is never pruned |
| Logging | Up to 300 bytes of Redmine error bodies logged at WARNING; user login and scopes at INFO on every request |
| Tests | The end-to-end OAuth test is a skip followed by `assert True`; the plan items are ticked anyway |
| Conventions | Version bumped on the feature branch; commit message not conventional |

Test run (Python 3.14, FastMCP 3.4.8): `main` 90 passed; PR branch 87 passed, 7 failed, 1 skipped.

**Outcome.** Closed unmerged (DR-002). The `/health` route and scope-based tool hiding are Phase 8 tasks.

## 3. Upstream changes

**FastMCP 3.0 → 3.4.8** [3]
- 3.2.0: loopback redirect URIs match any port; IdP-granted scopes preferred; transparent upstream token refresh. The refresh does not call `_extract_upstream_claims`, which causes RISK-001.
- 3.2.1: upstream claims passed into `AccessToken.claims["upstream_claims"]`, a place to keep granted scopes that survives refresh and restart.
- 3.4.0: configurable access token expiry; JWT handling moved to joserfc.
- 3.4.3 turned on a Host/Origin check by default; 3.4.4 reverted it.
- Per-tool `auth=require_scopes(...)` hides tools from tokens without the scope; it fits better than per-session `disable_components`.
- No breaking change for this server's `OAuthProxy` subclass up to 3.4.8.

**FastMCP 4.x.** 4.0.0 (2026-08-31) builds on MCP Python SDK 2 and the sessionless 2026-07-28 protocol, with breaking changes (httpx2, sampling and roots removed, `ctx.elicit` different on modern connections). 3.x still receives security fixes. Moving is in the backlog.

**MCP specification.** The current version is 2026-07-28: sessions and the `initialize` handshake removed, tool lists no longer vary per connection, dynamic client registration deprecated in favour of CIMD, `iss` recommended. FastMCP 3.x supports the protocol up to 2025-11-25.

**Redmine 7.0** (2026-06-30). Same Doorkeeper OAuth setup as 6.1: authorization code with refresh tokens, 2-hour token lifetime, scopes are permission names plus `admin`, no token introspection. New: webhooks.

## 5. Code and repo

- No `.github/` (no CI, Dependabot or image publishing), no lock file, no LICENSE or SECURITY.md, no `.gitattributes`.
- `pyproject.toml` has no build system, no dev dependencies and no pytest settings; `pytest-asyncio` is used but not declared.
- Tools carry no MCP annotations and return markdown strings; errors are returned as strings without the MCP error flag; 401, 5xx and network errors are not caught.
- `project_id` and wiki page titles go into URL paths without escaping.
- A new `httpx.AsyncClient` is created per request.
- `server.py` reads required settings with bare `os.environ[...]` at import time, so a missing setting raises `KeyError` with no message.
- CORS allows every origin.

These are tasks in Phases 7, 8, 9 and 11.
